# خادم وَفِّرْهَا صَحّ (Cloudflare Worker)

`worker.js` هو كود الخادم `blue-wind-40c9`: بوت الإدارة في تلجرام، وتتبع النقرات `/go/`،
وتنبيهات الأسعار، والآراء، وإحصائيات الزيارات. هذا الملف نسخة من الكود المنشور على Cloudflare،
وأي تعديل هنا لا يصل للخادم إلا بعد لصقه في محرر Cloudflare والضغط على **Deploy**.

لا تكتب أي توكن أو كلمة سر داخل الكود — المستودع عام. كل الأسرار في متغيرات الـWorker.

## ربط قاعدة البيانات D1 (الإصدار 6.4)

**لماذا؟** الخطة المجانية في KV تسمح بـ1000 كتابة يوميًا فقط. كل زيارة كانت تستهلك 3 كتابات وكل نقرة
كتابة، فعند حوالي 300 زائر يوميًا يتوقف تسجيل الزيارات والنقرات، ويتوقف معه بوت الإدارة
(لأنه يحفظ خطوات إضافة المنتج في KV). D1 يسمح بـ100 ألف كتابة يوميًا مجانًا.

**الخطوات** (من dash.cloudflare.com):

1. **أنشئ قاعدة البيانات:** Storage & Databases ← **D1 SQL Database** ← **Create** ← الاسم `wafartha-db` ← Create.
2. **اربطها بالخادم:** Workers & Pages ← `blue-wind-40c9` ← **Settings** ← **Bindings** ← **Add** ← **D1 database**
   - Variable name: `DB` (بأحرف كبيرة بالضبط)
   - D1 database: `wafartha-db` ← **Deploy / Save**
3. **حدّث الكود:** في نفس الـWorker اضغط **Edit code**، احذف كل الكود الموجود، والصق محتوى `worker.js` كاملًا، ثم **Deploy**.
4. **تأكد:** افتح رابط الخادم، يجب أن يظهر: `Wafartha Sah Bot v6.4 ✅ — D1`
   (إذا ظهر `— KV` فالربط في الخطوة 2 لم يُحفظ أو الاسم ليس `DB`).
5. **انقل البيانات القديمة:** أرسل للبوت `/migrate` مرة واحدة. يرد بعدد السجلات المنقولة.
6. أرسل `/stats` — في آخر الرسالة: «🗄️ التخزين: قاعدة البيانات D1 ✅».

الجداول تُنشأ تلقائيًا، ولا حاجة لكتابة أي SQL.

**الرجوع للخلف:** البيانات القديمة لا تُحذف من KV. لو حدثت مشكلة احذف الربط `DB` من Bindings
فيرجع الخادم للعمل على KV كما كان، أو الصق النسخة السابقة من `worker.js` من سجل GitHub.

## ما الذي يُحفظ أين

| البيانات | بدون DB | مع DB |
|---|---|---|
| النقرات والزيارات وسجل الأسعار والتنبيهات والآراء | KV | D1 |
| النسخة المؤقتة من المنتجات | KV | الذاكرة + D1 |
| خطوات إضافة المنتج في البوت، رموز X | KV | KV |
| المنتجات والصور | GitHub (`products.json` و `products/`) | GitHub |
